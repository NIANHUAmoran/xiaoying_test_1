# AI 辅助使用记录

本项目由 AI 编码助手依据用户提供的原题和统一规范完成本地实现。辅助范围包括读题、需求拆解、方案设计、Python 代码、单元测试、合成数据、示例运行与文档。未使用其他 Agent 协作，未套用第三方 Agent 框架。

关键实现选择包括：用 CLI 和标准库降低启动成本；真实模型与离线策略分离；通过确定性工具限制模型权限；把原始时间、候选建议、用户确认及保存结果分别存储；使用 SQLite 事务与唯一约束处理竞争和重复保存。用户随后提出文件配置需求，因此增加根目录 `.env` 自动加载和配置保密测试。

AI 助手实际执行了示例重建与 31 项测试，检查了 CLI 退出码、草稿数量、重复提交 ID、占用变化和错误处理。用户提供本地模型配置后，助手另行执行正常、冲突与信息缺失三条真实模型路径，核对了 SQLite 落盘事实。验证材料引用于 `03-evaluation.md`，原始运行输出保存在 `examples/`。

真实模型接入中发现提示词对待确认草稿的语义有歧义，助手根据失败运行澄清提示并重跑通过，保留修正前记录。真实 Trace 来自交付程序调用配置的服务，不使用编码助手的推理充当运行证据；其余 Mock 记录仍明确标记为离线，不扩大其证明范围。密钥只从本地配置加载，未展示在聊天或写入交付材料。

交付整理中，助手将原题、准备流程和提交草稿移出交付项目；验证脚本归入 tests，故障合成数据归入 data，提交信息并入 README。助手从实际输出提取独立 Trace，补齐各场景输入与评估引用，并运行结构与材料一致性核查。历史真实模型输出保留原始内容，未以重新命名或整理文件冒充新的模型调用。

用户选择题目、提出解题流程与文件配置要求，并在本地完成模型接口配置；尚未提供独立代码修改或亲自验收的记录，因此不代填这些贡献。提交前应如实补充自己读懂、修改、复核的具体位置及结果，特别是亲自核对硬性时间边界、同一份草稿的重复保存和真实模型路径。
